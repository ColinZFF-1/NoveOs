## 二、核心业务逻辑

### 2.1 项目生命周期

```
注册项目 → 初始化品类DNA → 加载大纲 → 启动流水线 → 逐章写作 → 完成
   │            │              │            │            │         │
   │            │              │            │            │         └─ status: completed
   │            │              │            │            └─ 每章: Director→Writer→Interceptor→Polish→Auditor
   │            │              │            └─ ThreadPoolExecutor 提交 _run_pipeline
   │            │              └─ init_from_outline: 写入 characters/items/debts/foreshadowing/outline/skill_tree
   │            └─ init_genre_dna: 根据 genre 注入句长/对话/道说比/IWR目标
   └─ register_project: 创建 StateManager + BatchWriter + 恢复已有进度
```

### 2.2 单章写作流水线（5阶）

```
Chapter N
    │
    ├─► Director
    │    输入: chapter_num + context(debts/foreshadowing/outline/characters/rules/genre_dna)
    │    输出: 任务卡（含标题、节拍表、钩子位置、情绪目标）
    │    注: 首次生成，重试复用
    │
    ├─► Writer
    │    输入: Director任务卡 + 品类DNA约束 + IWR约束 + 字数铁律
    │    输出: 初稿（纯中文正文）
    │    约束:
    │      - 标题必须写在正文最开头
    │      - 字数分配: 起20% / 承30% / 转30% / 合20%
    │      - IWR ≥ 2.0（每章至少提出3个问题，答案在0.3-0.7章内揭示）
    │      - 句长按品类DNA目标控制
    │      - 对话占比 25-45%
    │      - 他密度 < 2%
    │
    ├─► DeAI Interceptor
    │    输入: Writer初稿
    │    输出: issues列表 + repair_instruction（如有）
    │    作用: 检测并修复AI味文本
    │
    ├─► Polish（条件触发）
    │    输入: 初稿 + repair_instruction（如有）
    │    触发: 每3章1次 或 Interceptor发现issues
    │    输出: 润色后的纯正文
    │
    └─► Auditor（【升级】结构审计）
         输入: 最终正文
         计算:
           1. CJK字数 / 他密度 / 禁用词
           2. IWR = 问题数 / 答案数
           3. 句长 / 对话占比 / 微张力振荡
           4. 平台适配度 = 6维度100分制
           5. 品类DNA匹配度 = 句长+对话+他密度三维度匹配
         输出: audit_report（含 extra 字段承载全部结构指标）
         判定: QualityGates → PASS / WARN / BLOCKING
```

### 2.3 重试策略

```
QualityGates 判定 BLOCKING
    │
    ├─ 字数超标 → truncate_if_needed → 截断后重审计 → 非BLOCK则通过
    │
    ├─ 字数不足 → _call_expander 扩写 → 重审计 → 仍不足则注入扩写指令给Writer重试
    │
    └─ 其他（IWR不足/平台分过低/DNA不匹配）→ 注入修正指令给Writer重试
         修正指令示例:
         "本章IWR仅1.2，需增加悬念问题。请在转折处添加1-2个未解之谜，
          并在结尾留下明确钩子。"
```

### 2.4 状态更新（每章完成后）

```
_update_state_after_chapter(chapter_num, content, title)
    │
    ├─► chapter_history    → summary / word_count / mode / title
    ├─► projects           → current_chapter / status=writing
    ├─► chapter_metrics    → 【新增】IWR/平台分/DNA匹配/句长/对话/他密度/振荡
    ├─► emotion_history    → 【新增】nué/tián/shuǎng 密度（简化关键词估算）
    └─► orchestrator.db    → 持久化 status / current_chapter
```

## 四、关键算法

### 4.1 IWR 计算

```python
IWR = 问题数 / 答案数

问题来源:
  - 显式问句: ？结尾
  - 隐式悬念: 难道|莫非|究竟|到底|为何|怎么|会不会|是否

答案来源:
  - 揭示标记: 原来|终于|发现|明白|知道|看来|果然|竟然|居然|突然|顿时
```

### 4.2 平台适配度评分

```python
总分 = min(100, 章字数CV得分 + 章长得分 + 对话密度得分 + 句长得分 + 他密度得分 + 悬念节奏得分)

章字数CV(25分):
  CV<10% → 25 / <20% → 20 / <35% → 12 / else → 5

章长(20分):
  1500-2500字 → 20 / 2500-3500 → 15 / >=1000 → 8 / else → 3

对话密度(15分):
  25-45% → 15 / 15-55% → 10 / else → 5

句长(15分):
  18-28字 → 15 / 15-35字 → 10 / else → 5

他密度(15分):
  <1.0% → 15 / <2.0% → 12 / <3.0% → 7 / else → 3

悬念节奏(10分):
  钩子结尾 + IWR>=2.0 → 10 / IWR>=1.5 → 7 / else → 3
```

### 4.3 品类DNA匹配度

```python
匹配度 = (句长匹配分 + 对话匹配分 + 他密度匹配分) / 3

句长匹配:
  diff = |actual_sent - target_sent|
  score = max(0, 100 - diff * 5)

对话匹配:
  diff = |actual_dialogue - target_dialogue|
  score = max(0, 100 - diff * 200)

他密度匹配:
  actual_ta <= target_ta → 100
  else → max(0, 100 - (actual_ta - target_ta) * 5000)
```

### 4.4 微张力振荡

```python
段落张力 = (叹号数×3 + 动作动词数×2 + 极短句数×1) / 段落字数 × 100

振荡 = 紧张→释放→紧张的交替次数
（相邻段落张力变化 >5% 且方向相反时计数）
```

## 七、业务规则汇总

| 规则 | 优先级 | 触发条件 | 动作 |
|------|:------:|---------|------|
| IWR 硬约束 | P0 | Auditor 判定 | IWR < 2.0 → BLOCKING → Writer 重试 |
| 平台适配度 | P1 | Auditor 判定 | 等级 C → WARN → 提示优化 |
| 品类DNA匹配 | P1 | Auditor 判定 | 匹配度 < 60 → WARN → 提示调整句长/对话 |
| 字数超标 | P0 | QualityGates | 截断至 target + tolerance |
| 字数不足 | P0 | QualityGates | Expander 扩写 → 仍不足 → Writer 重试 |
| 长篇自适应 | P2 | chapter > 100 | 对话+5%、句长-2字、字数收紧±10% |
| 膨胀检测 | P2 | 每10章检查 | 最近10章字数增长>20% → 告警 |
| 情感坐标 | P2 | 每章完成后 | 关键词统计 → emotion_history |
| 禁用词过滤 | P1 | Auditor | 命中9个禁用词 → 标记 |
| 他密度控制 | P1 | Auditor | > 2% → WARN |
