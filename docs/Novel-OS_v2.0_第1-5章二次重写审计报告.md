## 五、问题根因深度分析

### 5.1 对话占比问题的三层根因

```
Layer 1: BeatPlanner（节拍分配师）
  → 六段式节拍表只规划"起/承/转/合"的情节推进
  → 没有专门的"对话场景"段落规划
  → SceneWriter 按照节拍表写，自然忽略对话

Layer 2: SceneWriter（场景写作师）
  → 虽然 system prompt 要求了对话占比 25%-45%
  → 但诡秘/悬疑品类的场景偏压抑、独处、内心戏
  → LLM 的"默认行为"是叙述+描写，对话需要额外"激活"
  → prompt 约束无法完全覆盖模型偏见

Layer 3: DialogueTuner（对话调优师）
  → 职责是优化已有对话的密度和道说比
  → 但无法"凭空创造"对话
  → 如果 SceneWriter 只写了 7.8% 的对话，DialogueTuner 最多优化到 10%
```

### 5.2 根本解决方案

**必须在 BeatPlanner 阶段就规划对话场景**：

在 `_call_beat_planner` 的 prompt 中增加：
```
【对话场景规划 - 必须包含】
在六段式节拍中，至少安排 3-5 个对话场景节点，标注：
1. 对话参与人物
2. 对话核心冲突（不是闲聊，必须推进情节或揭示秘密）
3. 每段对话预估字数（确保总对话占比≥25%）
```

这样 SceneWriter 在按照节拍表创作时，会明确知道"这里需要写一段对话"，而不是自由发挥时忽略对话。
