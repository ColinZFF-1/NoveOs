## 一、RAG 分析核心结论（优化驱动力）

### 1.1 追读唯一驱动因子：IWR

| 指标 | 高追读组 | 低追读组 | 皮尔逊相关 |
|------|:-------:|:-------:|:---------:|
| IWR | 3.0 | 1.2 | **r=0.898** |
| 微张力 | 28次/章 | 28次/章 | r=0.084 |

**结论**: IWR（信息扣留比）是追读的唯一独立驱动因子，微张力是自然涌现产物，不应直接控制。

### 1.2 平台适配度 6 维评分模型

```
平台适配分 = 章字数CV(25) + 章长(20) + 对话密度(15) + 句长(15) + 他密度(15) + 悬念节奏(10)
```

S级（≥85分）全部是 **2000字黄金章长 + 对话40-55% + 句长19-35字** 的组合。

### 1.3 品类 DNA

| 品类 | 句长 | 道/说比 | 对话占比 |
|------|:---:|:------:|:-------:|
| 言情 | 23 | 0.4:0.6 | 40% |
| 都市 | 25 | 0.4:0.6 | 40% |
| 玄幻 | 31 | 0.55:0.45 | 30% |
| 科幻 | 32 | 0.55:0.45 | 28% |

### 1.4 长篇自适应规则

- 63% 长篇结构终生稳定
- 34% 膨胀型（后期章变长）= 信息密度稀释信号
- 100章后自动调整：对话+5%、句长-2字、字数收紧±10%

## 六、流水线重构：4阶 → 7阶（Scheme A）

### 6.1 重构决策

用户明确选择 **Scheme A（拆分 Agent）**，优先质量而非延迟。

| 方案 | 延迟 | 质量 | 选择 |
|------|:---:|:---:|:---:|
| Scheme A（拆分Agent） | 60s/章 | ⭐⭐⭐ | ✅ |
| Scheme B（减负Writer） | 20s/章 | ⭐⭐☆ | ❌ |

### 6.2 7-Agent 流水线架构

```
Director ──→ BeatPlanner ──→ SceneWriter ──→ HookEngineer ──→ DialogueTuner ──→ Interceptor ──→ Polish ──→ Auditor
(任务卡)      (节拍分配)       (场景正文)        (钩子优化)          (对话调优)         (AI味扫描)     (润色)    (结构审计)
```

| Agent | 职责 | 从 Writer 拆出的规则 |
|-------|------|---------------------|
| **Director** | 生成任务卡（标题+节拍） | 保留 |
| **BeatPlanner** | 六段式节拍字数分配 | 字数分配 |
| **SceneWriter** | 场景正文自由创作 | 仅保留字数铁律+格式铁律 |
| **HookEngineer** | 开头/结尾钩子优化 | IWR≥2.0、章末钩子 |
| **DialogueTuner** | 对话密度+道说比 | 对话占比、道说比、对话簇≤3 |
| **Polish** | 去AI味润色 | 保留 |
| **Auditor** | 结构审计（IWR+平台分+DNA） | 保留，升级为教练模式 |
| **Expander** | 字数不足扩写 | 保留 |

### 6.3 智能回退策略

Auditor 判定 BLOCKING 时，不再全部回退 Writer，而是精准回退到对应 Agent：

| BLOCKING 原因 | 回退目标 | 修正指令 |
|--------------|---------|---------|
| IWR/钩子不足 | **HookEngineer** | 开头+1悬念，结尾+1-2未解之谜 |
| 对话/DNA不匹配 | **DialogueTuner** | 调整对话密度和道说比 |
| 句长/他密度 | **SceneWriter** | 拆分长句，减少人称代词 |
| 字数不足（Expander后仍不足） | **SceneWriter** | 扩写指令 |
| 字数超标 | 截断（无需回退） | — |
| 平台适配度低 | **全局修正** | 整体结构调整 |

### 6.4 Writer 减负后规则

SceneWriter 仅保留 **2 条铁律**：
1. **字数铁律**：每章中文字数严格控制在目标±容差内
2. **格式铁律**：禁止节拍标签、markdown，开头写标题

其余 6 条规则（IWR/对话/DNA/他密度/去AI味/对话簇）全部迁移给下游 Agent。

## 七、后续建议（P3）

1. **LLM 深度审计**: 取消 _call_auditor 中的注释，接入真实 LLM 审计，与结构审计形成互补
2. **膨胀检测告警**: 在 `_run_pipeline` 中每 10 章检查一次字数趋势，触发时自动收紧 tolerance
3. **追读力预测模型**: 用线性回归替换当前简单的 `_calc_reader_pull_score`，输入 IWR+平台分+DNA匹配
4. **前端指标面板**: 在 ChapterPreview 旁增加"本章结构指标"浮层，显示 IWR/平台等级/6维度雷达图
5. **大纲编辑器**: 新增 `POST /outline/{chapter}` 接口，支持前端直接编辑 questions/reveal_at/beat_pattern
