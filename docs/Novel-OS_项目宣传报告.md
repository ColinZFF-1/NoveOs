# Novel-OS 项目宣传报告

> **AI 驱动长篇小说写作操作系统**  
> 基于大语言模型的多 Agent 协作写作流水线，支持 120 章级长篇小说全自动生产  
> 已验证单章 4500+ 字、多项目并行的工业级写作能力  
> 报告日期：2026-06-01

---

## 一、项目概览

### 1.1 一句话描述

**Novel-OS 是全球首个面向长篇网文的 AI 写作操作系统**，通过 7 Agent 协作流水线、双层 CrewAI 调度架构、多层质量门禁系统，实现从大纲到成书的全自动写作流程。

| FastAPI 路由模块 | **15 个** |

```
后端：     Python 3.12 + FastAPI + SQLite + OpenAI SDK
```

## 二、系统架构

### 2.1 双层调度流水线

Novel-OS 采用创新的**双层 CrewAI 调度架构**：

```
┌─────────────────────────────────────────────────────────────┐
│                    内层流水线（每章执行）                       │
│                                                             │
│  Director ──→ BeatPlanner ──→ SceneWriter ──→ HookEngineer │
│                                                     │       │
│     │                                               ▼       │
│     │              DialogueTuner ──→ Interceptor ──→ Polish │
│     │                                               │       │
│     └───────────────────────────────────────────────▼       │
│                        Auditor（结构审计）                    │
│                              │                              │
│                     BLOCKING？──→ 智能回退修正 ──→ 重试      │
│                              │                              │
│                          PASS ──→ 保存 + 更新状态库           │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│               外层巡检（每 5-10 章触发）                       │
│                                                             │
│  Novel Architect ──→ Continuity Inspector ──→ Retcon Manager│
│        │                                              │     │
│        └──────────── Pacing Analyst ─────────────────┘     │
│                              │                              │
│                 反馈注入后续章节上下文                         │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 7 阶内层 Agent 职责矩阵

| 序号 | Agent | 职责 | 输入 | 输出 |
|------|-------|------|------|------|
| 1 | **Director** | 读取大纲+人设+规则，生成本章任务卡 | 大纲/人物状态/债务/伏笔/规则 | 任务卡（含标题） |
| 2 | **BeatPlanner** | 将任务卡拆为六段式节拍分配表 | 任务卡 + 品类DNA | 六段字数分配+核心内容 |
| 3 | **SceneWriter** | 按节拍表创作场景正文 | 节拍分配表 + 修正指令 | 场景初稿 |
| 4 | **HookEngineer** | 优化开头/结尾，确保IWR和钩子密度 | 场景初稿 + IWR目标 | 钩子优化版 |
| 5 | **DialogueTuner** | 调整对话占比和道说比 | 钩子版 + 品类DNA | 对话优化版 |
| 6 | **Polish** | 全文去AI味润色 | 对话版 + 拦截器反馈 | 润色版正文 |
| 7 | **Auditor** | 5维结构审计（对话/因果/弧光/信息密度/钩子） | 润色版正文 | 审计报告 + JSON评分 |

### 2.3 外层 CrewAI 4 Agent 巡检系统

| Agent | 触发条件 | 职责 |
|-------|---------|------|
| **Novel Architect** | 每 5 章 | 全书架构健康度巡检，检测偏离、角色遗忘、伏笔积压 |
| **Continuity Inspector** | 每 5 章 | 跨章一致性检查，发现人物/情节/时间线矛盾 |
| **Retcon Manager** | 发现致命矛盾时 | 自动生成回溯修正方案，注入后续章节 |
| **Pacing Analyst** | 每 10 章 | 节奏诊断，生成下 10 章情绪目标指引 |

## 三、核心技术创新

### 3.1 DeAI 拦截器（零 LLM 成本去 AI 味）

21 类黑名单词库，纯正则匹配，毫秒级扫描，无需额外 API 调用：

- 英文残留检测（harness/navigate/cultivate 等）
- AI 标志性表情（"嘴角微微上扬""眼眸中闪过一丝"等）
- 氛围模板（"空气中弥漫着一种说不清的"等）
- 过渡废词（"就在这时""殊不知"等）
- AI 高频副词（缓缓/微微/轻轻/默默/悄然/下意识）
- 自动标红 → 占位符注入 → 强制 Polish 重写

### 3.2 ChapterValidator 统一校验层

合并旧版 Interceptor(230行) + QualityGates(157行) + 8 Guards(~900行)，消除三重重复校验和阈值冲突：

| 级别 | 检查项 | 阈值 |
|------|--------|------|
| **BLOCK** | 字数不足/超标 | 4000-5000 字 |
| **BLOCK** | 他字密度超标 | ≤ 10% |
| **BLOCK** | 红线词 | 0 容忍 |
| **WARN** | 禁用模式命中 | > 3 个 |
| **WARN** | 对话占比异常 | 25%-45% |
| **INFO** | 感官细节密度 | 每 500 字 ≥ 1 处非视觉 |

### 3.3 追读力评分算法（Reader Pull Score）

多维度量化评估每章的读者吸引力：

```
追读力 = 基础分(3.0)
       + 字数得分(min(word_count/1000, 3.0))
       + 质量门得分(PASS=1.5, WARN=0.8, BLOCKING=0)
       + 对话密度得分(min(对话占比 × 2.0, 2.0))
       + 节奏得分(1.0 - 重试次数 × 0.3)

满分 10.0，BLOCKING 直接归零
```

### 3.4 品类 DNA 匹配系统

基于 RAG（检索增强生成）分析目标平台爆款小说，提取品类 DNA 基准：

- **平均句长**：匹配品类读者阅读习惯
- **道说比**：控制"道/说"使用比例
- **对话占比**：言情 40-55%，爽文 25-40%
- **IWR（信息扣留比）**：≥ 2.0 确保悬念密度
- **平台适配分**：番茄小说/七猫等平台特定因子

### 3.5 SQLite 跨章状态库（world_state.db）

11 张表实现完整的故事世界状态管理：

| 表 | 用途 | 关键字段 |
|----|------|----------|
| `projects` | 项目注册表 | 类型/平台/进度/目标 |
| `character_states` | 人物状态 | 位置/情绪/秘密/对话指纹/肢体语言 |
| `outline` | 章纲规划 | 核心事件/打脸方式/情绪配比/技能解锁 |
| `debts` | 债务时间表 | 悬念埋入章/回收章/优先级 |
| `foreshadowing` | 伏笔时间表 | 埋入章/提示强度/回收章 |
| `consistency_rules` | 写作硬规则 | 人设/设定/节奏约束 |
| `skill_tree` | 技能树 | 每章解锁能力/使用限制 |
| `chapter_history` | 已写摘要 | 字数/标题/时间戳 |
| `emotion_history` | 情感坐标 | 虐/甜/爽三维 + LLM 标注 |
| `chapter_snapshots` | 章节快照 | 支持回滚 |
| `runtime_logs` | 运行日志 | Agent 级别执行追踪 |

### 3.6 多项目并行调度器（Orchestrator）

- **单项目串行**：保证故事连续性
- **跨项目并行**：ThreadPoolExecutor Worker Pool（最大 10 Worker）
- **失败隔离**：Worker 崩溃只影响当前章节
- **断点续传**：从全局数据库恢复进度
- **暂停/停止/恢复**：完整的流水线生命周期管理
- **全局统计**：项目数/活跃数/完成数/健康度

### 3.7 事件总线 + WebSocket 实时推送

- 10 种事件类型：PIPELINE_START/PAUSE/COMPLETE、CHAPTER_START/COMPLETE/ERROR、OUTER_CREW 巡检事件等
- 按项目 ID 订阅广播
- 跨线程桥接（Worker 线程 → 主线程事件循环）
- 前端实时展示 Agent 进度和审计结果

## 四、质量保障体系

### 4.1 质量门禁多级拦截

```
第 1 层：Prompt 内嵌铁律（字数/去AI味/格式 → 写入时约束）
    ↓
第 2 层：ChapterValidator 快速扫描（零成本，毫秒级）
    ↓ Pass
第 2 层 WARN → 第 3 层：Polish 润色（LLM 调用，有策略触发）
    ↓
第 4 层：Auditor 深度审计（LLM 调用，5 维评分 JSON）
    ↓
BLOCKING？→ 智能回退（对应 Agent 接收精准修正指令，最多 3 次重试）
```

### 4.2 字数铁律保障

- 单章目标 4500 字，允许误差 ±450
- 六段式节拍字数分配：起(20%)→承1(30%)→承2(30%)→转(20%)
- 每个节拍完成自检节点
- 不足 → Expander 扩写
- 超限 → 句子边界智能截断
- 最多 3 次重试

### 4.3 去 AI 味 6 大硬规则

1. **他字密度 ≤ 10%**：超出触发 BLOCK 级拦截
2. **禁用词零容忍**："缓缓/微微/淡淡/轻轻/默默/悄然/莫名/忽然/竟然/突然/殊不知" 等 18 个禁用词
3. **禁止"不是X，是Y"句式**：全文最多 1 处
4. **情绪感知模糊化**：禁止精确测量式心理描写
5. **环境描写做减法**：只保留带叙事功能的锚点
6. **比喻私有化**：禁止公共库存比喻

### 4.4 9 大 Guard 门禁系统

| Guard | 级别 | 职责 |
|-------|------|------|
| **quality_gate_guard** | BLOCKING | 字数/他字密度/禁用词/红线词硬指标 |
| **interceptor_guard** | BLOCKING | AI 模板痕迹扫描 |
| **causality_guard** | WARN | 场景因果自洽性 |
| **continuity_guard** | BLOCKING | 人物/时间线/设定连续性 |
| **hallucination_guard** | BLOCKING | 人物幻觉检测 |
| **pacing_guard** | WARN | 节奏把控 |
| **reader_pull_guard** | INFO | 追读力提醒 |
| **voice_consistency_guard** | WARN | 文风一致性 |

## 六、可扩展性与开放性

### 6.1 平台适配层

通过 `platforms/*.yaml` 配置文件适配不同小说平台：

- **番茄小说**（fanqie.yaml）：A+级评分体系，品类偏好建模
- **七猫小说**（qimao.yaml）：流量分发策略，用户画像匹配

`platform_scorer.py` 提供可插拔的平台评分接口。

### 6.2 Guard 插件系统

插件化的门禁架构，支持自定义 Guard 开发和热注册：

```python
# 任意 Python 模块均可注册为 Guard
from core.guards.registry import guard_registry
from core.guards.base import BaseGuard

class MyCustomGuard(BaseGuard):
    guard_id = "my_custom_guard"
    description = "自定义质量检查"
    default_level = "WARN"

    def run(self, content, context):
        # 自定义检查逻辑
        return GuardResult(...)

guard_registry.register(MyCustomGuard())
```

### 6.3 LLM Provider 灵活切换

- 主 Provider → Fallback Provider 自动容灾
- 支持 OpenAI 格式 API（DeepSeek/SiliconFlow/自有部署）
- `litellm` 兼容层支持 100+ LLM Provider
- 环境变量注入，配置与代码分离

### 6.4 外部数据注入

- `book_data.py` 创作数据文件（大纲/人设/债务/伏笔/规则/技能）
- `book.yaml` 项目配置文件
- `interceptor_rules` 外部 JSON 黑名单注入
- `rag_analysis` 品类 DNA 数据驱动
