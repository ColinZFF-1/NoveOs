# Novel-OS 去AI味与大纲注入 结论优化方案 v1.0

> 基于 deepseek-v4-flash/pro 前2章测试、卡兹克去AI味体系适配、网文写作规律 的综合结论

---

## 一、当前系统诊断（5个致命断层）

| 断层 | 表现 | 根因 |
|------|------|------|
| **数据流断层** | 大纲文件有"林默的选择/代价/钩子"，数据库 outline 表只有9个字段，Agent 读到的信息密度不足 | 没有大纲→数据库的同步管道 |
| **术语遵循断层** | "永夜集团/规则裂隙审计/存在性折旧/留白者" 全部缺失 | 设定铁律埋在 user prompt 中段，模型权重不足 |
| **格式约束断层** | v4-pro 完全不输出"第X章：标题"格式 | reasoning 模型对格式指令遵循度低 |
| **去AI味断层** | 当前是"减法"（禁用词扫描），没有"加法"（人格注入） | DeAIInterceptor 只有 BANNED_PATTERNS，没有 author_persona |
| **质量盲区** | 没有"契诃夫之枪"回调检查、没有"升番逻辑"检查、没有"对话指纹"检查 | ChapterValidator 只检字数/他字/禁用词 |

---

## 二、优化方案（5层改造）

### 第1层：数据管道——大纲入库脚本

**目标**：让 `world_state.db` 成为唯一数据源，Agent 不再读 markdown 文件。

**新增3个脚本**：

```
scripts/
  import_outline.py      # 解析 markdown 大纲 → 写入数据库
  build_term_dict.py     # 从大纲提取术语字典 → 写入数据库
  preflight_check.py     # 写作前预检，不通过拒绝启动
```

**import_outline.py 输出**：

```sql
-- 扩展现有 outline 表或新增 chapter_specs 表
chapter | title | core_event | protagonist_choice | cost | hook | 
character_relations | world_rules | key_terms | emotion_curve | 
protagonist_arc_point | cliffhanger_type
```

> 把大纲中 `**林默的选择**`、`**代价**`、`**钩子**`、`**人物关系**` 等结构化段落，全部按字段入库。

**build_term_dict.py 输出**：

```sql
CREATE TABLE term_dict (
    term TEXT PRIMARY KEY,        -- "永夜集团"
    category TEXT,                -- "公司名"
    first_chapter INTEGER,        -- 1
    description TEXT,             -- "群体性异化共振的宿主"
    mandatory_chapters TEXT       -- "1,2,3,4,5"（必须在哪些章出现）
);
```

**preflight_check.py 检查项**：
1. 所有章节的大纲数据是否完整（core_event + hook + cost 非空）
2. term_dict 是否已生成
3. character_states 是否已初始化（林默/苏晚/张经理的基础设定）
4. 上一章的写作结果是否存在（连续性检查）

---

### 第2层：Prompt工程——术语铁律前置

**当前问题**：设定铁律在 user prompt 中段，模型（尤其是 reasoning 模型）对中段指令的权重远低于开头。

**改造方案**：

```
[system prompt 最前面]
你是诡秘职场小说《入职诡秘公司：我的工牌不对劲》的专属写作Agent。

【世界观铁律——出现任何一条错误，整章废弃重写】
1. 公司名绝对必须是"永夜集团"，禁止出现"云鼎科技"或任何替代名称
2. 主角异能必须称为"规则裂隙审计"，禁止用"发现漏洞/看出问题"等替代描述
3. 异能代价必须称为"存在性折旧"，禁止用"副作用/后遗症"等替代描述
4. 晚期被改造员工必须称为"留白者"，禁止用"行尸走肉/空壳"等替代描述
5. 主角的职业背景是前大厂HR裁员优化师，裁过372人，这个数字不准改

【人物指纹——对话调优时必须逐句核对】
- 林默：精确、带数字、像HR谈判，"第12条，主语是谁？"
- 苏晚：短句、冷、不带感情，"别碰。系统会标记。"
- 张经理：像公司制度条文，没有主语，"入职须参与破冰游戏。"
- 陈雨：颤音、断句、自我否定，"我、我不行的……"

【网文禁区——出现即FAIL】
- "不知道为什么/仿佛/似乎/好像/他意识到"
- "一些/实际上/在一定程度上"
- "被拖走/被吞噬/被格式化"（改成主动描述：无数只手从地板里伸出来扣住脚踝往下拽）
- 公共比喻（"像被风吹动的纸片"→锚定到主角记忆："和上个月被裁的UI设计师一样"）
```

**关键变化**：
- 从 user prompt 中段 → **system prompt 最前面**
- 从"建议性描述" → **"出现错误即废弃重写"的绝对铁律语气**
- 新增**人物对话指纹**，不是"每个人说话不同"，是**逐句核对**

### 第3层：人格注入——author_persona

**当前问题**：DeAIInterceptor 只有 BANNED_PATTERNS（减法），没有 author_persona（加法）。

**改造方案**：在 `book.yaml` 新增 `author_persona` 字段：

```yaml
author_persona:
  voice: "冷峻观察者"
  core_wound: "一个冷静到残忍的前HR，用裁人的精确度来分析吃人的规则，偶尔在数字里看见自己也被裁掉了"
  sentence_rhythm:
    - "紧张场景：连续5句不超过10个字，制造窒息感"
    - "规则宣读后：用……省略号沉默，让读者自己补完恐惧"
    - "死亡确认后：单句号成段，制造空白停顿"
  sensory_priority:
    - "触觉>听觉>视觉"  # AI 默认视觉优先，网文需要恐惧的生理触感
  forbidden_rhetoric:
    - "概括性时间：过了一会儿/不久之后"
    - "情绪标签：恐惧/绝望/愤怒"
    - "被动语态"
    - "假设性例子：比如有一次"
  signature_moves:
    - "数字恐怖：精确到秒的倒计时、存在性折旧百分比、裁掉第373人"
    - "反身动词：他看见自己的手在抖"
    - "动作先于心理：先写行为，再写（或不写）心理"
    - "二选一暴力：遵守规则=被改造。违反规则=被吞噬。没有第三条路。"
```

**系统落点**：
- `Director` 阶段：把 author_persona 注入 system prompt
- `SceneWriter` 阶段：用 sensory_priority 指导五感分配
- `DialogueTuner` 阶段：用人物指纹逐句核对
- `Polish` 阶段：用 signature_moves 检查是否命中

### 第4层：质量门禁——新增3个检查器

**当前 ChapterValidator 盲区**：只有字数/他字/禁用词/对话占比/大纲遵循，缺少：

#### 4.1 契诃夫之枪检查器（ChekhovGunChecker）

**规则**：
- 前3章埋的意象（工牌磨损、培训室椅子间距、PPT黑底白字），必须在后3章以变体形式 callback
- callback 不是"直接提到"，是"在类似场景中以类似感官出现"
- 第5章仍未 callback 第1章意象 → WARN

**示例**：
```
第1章：工牌边缘被磨得卷曲 → 第4章：留白者的工牌边缘也有同样的卷曲痕迹
第2章：消防通道的灰色油漆门 → 第5章：B3层的门也是同样的灰色，油漆更斑驳
```

#### 4.2 升番逻辑检查器（EscalationChecker）

**规则**：
- 每章冲突必须比上一章升级
- 升级维度：个人→团队→组织→系统→存在
- 如果第3章压迫感 ≤ 第2章 → BLOCK

**示例**：
```
第1章：个人层面（林默一个人的工牌异常）
第2章：团队层面（同事死亡，集体恐慌）
第3章：组织层面（KPI面谈，生理机能扣除）
第4章：系统层面（B3层留白者大军）
第5章：存在层面（存在性折旧23%，身体开始"留白"）
```

#### 4.3 IWR密度检查器（InformationWithholdingChecker）

**规则**：
- 每章结尾必须有 ≥2 个"已回答的问题"和 ≥3 个"新问题"
- 已回答的问题必须是"读者自己推出来的"，不是"旁白直接告诉的"
- 新问题必须是"主角看到了但看不懂的细节"，不是"作者故意卖关子"

### 第5层：模型策略——双轨制

**当前问题**：deepseek-v4-flash/pro 是 reasoning 模型，content 输出特性不稳定（格式丢失、术语遵循差），且速度极慢（pro 17分钟/2章）。

**改造方案**：**双轨制**，不是二选一，是**分阶段用不同模型**。

```
Director（任务卡）     → deepseek-chat（V3）
  └─ 原因：任务卡需要严格遵循格式和术语，V3 指令遵循度更高

BeatPlanner（节拍分配） → deepseek-chat（V3）
  └─ 原因：节拍分配是结构化输出，V3 更稳定

SceneWriter（正文写作） → deepseek-v4-pro
  └─ 原因：正文需要创造力和氛围营造，pro 的 reasoning 质量更高

HookEngineer（钩子优化） → deepseek-chat（V3）
  └─ 原因：钩子优化需要精确的 IWR 计算，V3 更听话

DialogueTuner（对话调优）→ deepseek-chat（V3）
  └─ 原因：对话指纹需要严格遵循，V3 更严格

Polish（润色）          → deepseek-v4-pro
  └─ 原因：润色需要文学质感，pro 的文采更好

Auditor（审计）         → deepseek-chat（V3）
  └─ 原因：审计需要精确的指标计算，V3 更稳定
```

**fallback 策略**：
- V3 调用失败 → 自动降级到 v4-pro
- v4-pro 调用失败 → 自动降级到 v4-flash

## 三、执行优先级（P0-P3）

| 优先级 | 事项 | 预估工时 | 影响 |
|--------|------|---------|------|
| **P0** | `import_outline.py` + `build_term_dict.py` | 2h | 解决数据流断层，所有后续改造的基础 |
| **P0** | 把设定铁律从 user prompt 移到 system prompt 最前面 | 30min | 立刻提升术语遵循度 |
| **P1** | `preflight_check.py` | 1h | 避免写到一半发现数据缺失 |
| **P1** | `book.yaml` 新增 `author_persona` 字段 | 1h | 从减法变加法，注入人格 |
| **P2** | 双轨制模型策略 | 2h | 解决速度和格式约束问题 |
| **P2** | IWR密度检查器 | 1.5h | 提升追读力 |
| **P3** | 契诃夫之枪检查器 | 2h | 提升作品感 |
| **P3** | 升番逻辑检查器 | 1.5h | 提升节奏感 |

---

## 四、一句话验收标准

> **跑完 P0-P1 后，重新生成第1章，检查：**
> 1. "永夜集团"出现 ≥1 次
> 2. "规则裂隙审计"出现 ≥1 次
> 3. "存在性折旧"出现 ≥1 次
> 4. "留白者"出现 ≥1 次
> 5. 标题格式正确："第1章：XXX"
> 6. 全篇无"不知道为什么/仿佛/似乎/他意识到"
> 7. 对话符合人物指纹（林默带数字、苏晚短句冷、张经理像条文）

**7项全过 = P0-P1 改造成功。**
