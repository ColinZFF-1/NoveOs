1. **对话占比严重偏低 —— 最突出问题**
   - 5章全部低于 25% 目标，均值仅 **15.6%**
   - 第3章仅 13.5%，第5章仅 13.1%
   - **根因分析**：
     - SceneWriter 的 system prompt 中明确说"你拥有创作自由，不需要控制 IWR、对话占比、句长、DNA 匹配等结构指标。这些由下游 Agent 负责优化。"
     - 虽然 Writer prompt 中增加了对话铁律，但 SceneWriter **不读取 Writer prompt**，它读取的是 BeatPlanner 生成的节拍分配表
     - DialogueTuner 下游优化时，由于原文对话太少，无法凭空"变出"对话
   - **修复方向**：必须在 **SceneWriter 的 system prompt** 中直接写入对话占比要求，因为对话必须在创作源头就嵌入，不能靠下游调优

   - 第3-5章首行：`第3章：KPI面谈` / `第4章：静默运维` / `第5章：凌晨的裂隙` ✅
   - **根因分析**：SceneWriter system prompt 中"你拥有创作自由"的表述削弱了格式铁律的权威性
   - **修复方向**：在 SceneWriter system prompt 中明确"格式铁律不属于创作自由范畴，必须严格遵守"

## 五、代码问题追踪

### 5.1 新发现的问题

| # | 问题 | 严重度 | 说明 |
|---|------|:------:|------|
| 1 | SceneWriter 无视格式铁律 | 🔴 高 | system prompt 中"创作自由"表述削弱了格式约束，导致第1、2章未写标题 |
| 2 | 对话铁律未触达 SceneWriter | 🔴 高 | Writer prompt 中的对话要求对 SceneWriter 无效，SceneWriter 只读取 BeatPlanner 的节拍表 |
| 3 | Auditor JSON 解析反复失败 | 🟡 中 | 4/5章出现 JSON 解析错误，Auditor 的 prompt 可能要求了过于严格的 JSON 格式 |
| 4 | 第4章字数不足触发扩写 | 🟡 中 | 第一次生成仅3728字，触发 Expander 扩写后才达标，说明 SceneWriter 字数控制仍不稳定 |

### 5.2 建议修复方案

**方案A：强化 SceneWriter 约束（推荐）**

在 `_call_scene_writer` 的 system prompt 中：
1. 删除"你拥有创作自由"的表述，改为"你拥有情节和描写层面的创作自由，但格式铁律和对话占比必须严格遵守"
2. 将对话占比要求直接写入 system prompt（而非 user prompt 中的 Writer 分支）
3. 将标题格式要求直接写入 system prompt

**方案B：标题兜底机制**

在 `write_chapter` 保存前：
1. 检查正文首行是否为 `第N章：标题` 格式
2. 如果不是，从 Director 任务卡中提取标题，自动插入到正文开头
3. 这样即使 SceneWriter 漏写标题，也能自动补全

**方案C：Auditor JSON 容错**

在 Auditor 调用后增加 JSON 解析容错：
1. 解析失败时不抛出异常，而是用正则从 Markdown 文本中提取关键指标
2. 或简化 Auditor 的输出格式要求，从 strict JSON 改为 Markdown 表格
