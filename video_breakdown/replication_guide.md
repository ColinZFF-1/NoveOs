### 4.2 选题扫描 Agent 实现（`/topic-scan`）

**Prompt 模板**（保存为 `90_System/Prompts/p-topic-research.md`）：

```markdown
# 选题调研 Agent Prompt

## 角色
你是一个资深内容策略师，负责为[领域]内容创作者发现和评估选题。

## 任务
扫描以下信息源，生成今日选题备忘录（3-5个选题）：

### 信息源（按优先级）
1. 微博热搜 / 百度热搜 / 抖音热搜 — 大众热点
2. 知乎热榜 / 即刻 — 深度讨论
3. 36氪 / 虎嗅 / 晚点 — 行业动态
4. Reddit / Hacker News — 海外视角
5. 我的 Obsidian 知识库 — 历史积累与缺口

### 选题评估维度（每项 1-5 分）
- **热度**：话题当前关注度
- **持久度**：是否是短期热点还是长期趋势
- **匹配度**：与我的领域/风格的契合程度
- **差异度**：我有没有独特视角？别人没写到的地方？
- **素材丰度**：知识库里有多少相关素材？

### 输出格式
对每个选题输出：
\`\`\`
## 选题：[一句话标题]
- 来源：[从哪里发现的]
- 热度：⭐x  持久度：⭐x  匹配度：⭐x  差异度：⭐x  素材：⭐x
- 核心角度：[独特的切入角度]
- 3个关键论点：
  1. ...
  2. ...
  3. ...
- 目标读者：[谁会看]
- 关联笔记：[知识库中的相关笔记链接]
\`\`\`

### 输出位置
保存到 `20_Topics/Pending/YYYY-MM-DD-topic-scan.md`
```

**执行方式**：

```bash
# 在 Obsidian vault 根目录执行
claude --prompt "$(cat 90_System/Prompts/p-topic-research.md)" \
       --output 20_Topics/Pending/$(date +%Y-%m-%d)-topic-scan.md
```

### 4.3 大纲生成 Agent 实现（`/outline`）

```markdown
# 大纲生成 Agent Prompt

## 输入
选题调研报告：[文件路径]

## 任务
基于选题调研报告，生成：
1. SCQA 结构大纲
2. 5 个备选标题（不同风格）

### SCQA 大纲结构
- **S (Situation)** — 情境：用具体场景/故事引入
- **C (Complication)** — 冲突：矛盾点、反常、痛点
- **Q (Question)** — 问题：核心要回答的问题
- **A (Answer)** — 回答：你的核心观点和论证框架

### 大纲要求
- 每个部分标注预计字数
- 标注需要插入案例/数据的位置
- 标注可以从知识库引用的素材
- 标注需要人工补充的部分（⚠️ 人工补充）

### 5 个标题风格
1. 悬念式 — 激发好奇心
2. 数字式 — 清晰可量化
3. 对比式 — 制造张力
4. 场景式 — 代入感强
5. 反常识式 — 打破认知

### 输出位置
保存到 `30_Drafts/draft-[slug]/outline.md`
```

```markdown
## 写作规则
1. **开头**：用具体场景/故事/对话切入，不用"在当今..."
2. **正文**：每段一个核心观点，观点→论据→案例→小结
3. **转折**：用"但其实""真正的问题是""更深一层看"等做段落衔接
4. **结尾**：回扣开头，给出行动建议或思考题
5. **金句**：每 500 字至少 1 句可独立传播的金句
6. **字数**：[你的标准]

## 禁止事项
- 禁用词：赋能、抓手、闭环、底层逻辑、颗粒度、对齐
- 禁用开头："随着...的发展""在当今...时代""众所周知"
- 禁用结尾："综上所述""总而言之""最后"

## 案例和数据
- 优先使用知识库中已有的真实案例
- 如需虚构案例，标注 [示例]
- 数据必须标注来源

## 输出位置
保存到 `30_Drafts/draft-[slug]/draft-v1.md`
```

### 4.5 去 AI 味润色 Agent（`/polish`）

**Prompt 模板**（保存为 `90_System/Prompts/p-polish.md`）：

```markdown
# 反 AI 味润色 Agent Prompt

## 输入
初稿文件：[文件路径]

## 润色规则（句式破坏六式）
1. **动词前置**：把动词从句子中间移到开头
2. **感官锚定**：每 500 字至少出现一个感官描写（看到的/听到的/闻到的）
3. **跳切留白**：段落之间不要用"但是""然而"硬连接，留出让读者自己填补的缝隙
4. **情绪物化**：把抽象情绪变成具体物品（"焦虑像桌上那杯凉透的咖啡"）
5. **未完成句**：适当使用断裂的、不完整的句子
6. **视角监狱**：保持第一人称或明确的叙述者视角，不要跳出上帝视角

## 他字密度检查
- "他/她/它/他们/她们/它们"的出现频率不应超过总字数的 0.5%
- 用具体名称替代代词

## 禁用词扫描
- 检查并替换：赋能、抓手、闭环、底层逻辑、颗粒度、对齐、复盘、倒逼

## 对话/引用注入
- 至少添加 1 处直接引语（真实的或模拟的对话）
- 至少引用 1 个具体的人名/书名/产品名

## 输出
- 润色后的终稿
- 润色变更清单（改了什么）
- 位置：`30_Drafts/draft-[slug]/draft-final.md`
```

### 4.6 发布与回流 Agent（`/publish`）

```
/publish 命令执行流程：

1. 确认终稿 → 人工最终审核
2. 同步到飞书多维表格 → 记录发布元数据
3. 推送飞书通知 → "新文章已发布：[标题]"
4. 知识回流：
   ├── 在 40_Published/ 创建发布记录
   ├── 提取文章中的新概念 → 50_Knowledge/Concepts/
   ├── 提取文章中的金句 → 60_Content_Library/Quotes/
   └── 更新相关笔记的双向链接
5. Git commit + push → 版本归档
6. 更新选题状态 → 20_Topics/Completed/
```

### 第三阶段：飞书打通（第 6-7 天）

**验收标准**：
- 飞书发"选题扫描"→ 5 分钟内收到选题备忘录
- 飞书发"搜一下知识库 xx"→ 返回相关笔记
- 每天早上 8:00 → 收到晨间简报

### 第四阶段：自动化流水线（第 8-10 天）

**目标**：四段式流水线稳定运行

```
□ 编写 topic-scanner.py（选题自动扫描脚本）
□ 编写 feishu-sync.py（飞书数据同步脚本）
□ 编写 publish.sh（一键发布脚本）

□ 配置 Git 自动提交
```

**验收标准**：

## 七、关键技术决策对比

### 7.1 为什么选 Claude Code 而不是其他 Agent

| 维度 | Claude Code | Gemini CLI | LangChain | Coze/Dify |
|------|------------|------------|-----------|-----------|
| 文件系统操作 | ✅ 原生支持 | ✅ 支持 | ⚠️ 需配置 | ❌ 受限 |
| MCP 协议 | ✅ 一等公民 | ⚠️ 部分支持 | ⚠️ 需插件 | ❌ 不支持 |
| Obsidian 集成 | ✅ 直接读写 md | ✅ 直接读写 | ⚠️ 需适配 | ❌ 需导出 |
| Git 集成 | ✅ 内置 | ⚠️ 手动 | ❌ 需脚本 | ❌ 不支持 |
| 上下文长度 | 200K | 1M+ | 取决于模型 | 取决于平台 |
| 中文质量 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |
| 本地运行 | ✅ | ✅ | ✅ | ❌ 云端 |
| 定价 | 按 token | 按 token | 取决于模型 | 订阅制 |

### 7.2 MCP 工具选型

| 用途 | 推荐工具 | 理由 |
|------|---------|------|
| 搜索引擎 | Tavily MCP | 专为 AI Agent 优化，返回结构化结果 |
| Obsidian 高级检索 | enquire-mcp | 44 个工具，混合 BM25+向量+Cross-Encoder |
| 飞书集成 | 飞书官方 MCP | 原生支持，消息+多维表+文档 |
| 图片搜索 | Unsplash MCP | 无版权图片，适合配图 |
| 网页抓取 | Scrapling MCP | 反反爬，适合抓公众号等 |
| Git 操作 | Claude Code 内置 | 无需额外 MCP |
| 知识库记忆 | agent-brain 模式 | 15 条命令，持续累积知识 |

## 九、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| AI 生成内容质量不稳定 | 需大量人工返工 | 持续迭代 prompt + 建立质量 checklist |
| API 调用失败/限流 | 流水线中断 | DeepSeek 做备用 + 本地缓存 |
| 飞书机器人被封 | 消息入口失效 | 终端 CLI 做备用操作方式 |
| 知识库膨胀导致检索变慢 | Agent 效率下降 | 定期归档 + 混合检索 + 索引优化 |
| AI 幻觉编造数据 | 发布错误信息 | 事实核查环节 + 标注数据来源 |
| Git 冲突 | 知识库损坏 | 定期备份 + 分支策略 |
